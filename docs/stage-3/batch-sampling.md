## 一次执行固定计划

```bash
.venv/bin/python -m fin_feature.cli sample-batch \
  --plan examples/sample-plans/stage3-eight-companies.json \
  --output-dir data/new-batch
```

计划限制 1-8 家不同 SH/SZ 公司、1-2 个年末日期，默认样本为茅台、美的、宁德时代、三一、万科、招行、平安、中信证券，2023/2024 两年。名称和样本组是人工选择标签，不是生产行业分类。不会扩大为全市场、自动翻页重试或写业务库；每家沿用最多四请求的 source-sample。间隔顺序执行，任一家公司失败后记录原因并继续下一家。

输出每公司证据/报告，以及 summary.json、summary.md。分母始终为计划公司数×报告期数×6 字段，包含失败公司和双方均缺失字段。区分：请求/解析完成、双方有效数字覆盖、口径一致/冲突、官方参考核查。采到数字不代表核验通过；official_reference_checked_pairs=0 明示本命令未执行官方报表核查，历史可见性仍未知。每家公司记录原始文件路径、输入 SHA-256、清单哈希和错误。

退出 0=计划项目全部口径可比且一致；1=采集完成但有缺失/不可比/差异；2=至少一家公司失败或计划/输出错误。空计划、重复公司、超范围和已有输出目录直接拒绝。

## 复用已有采样

计划公司可指定 reuse_sample 路径，CLI 将相对路径按计划文件目录解析。明确指定复用后不重新请求，也不在损坏时静默回退联网。只读重核四份响应的 gzip/哈希/大小、成功状态、公司/日期，重新映射并与保存 JSON 逐行比较；重新生成本次汇总，不修改旧采样目录。输入路径在新计划副本中保存，引用的旧证据目录须保留。

对于四份 HTTP 响应均已保存、仅因旧解析器拒绝而失败的样本，可显式离线重建到新目录：

```python
from fin_feature.sample_batch import rebuild_saved_sample
rebuild_saved_sample('/path/failed-sample', '/path/new-rebuilt-sample')
```

重建核验原体后使用当前映射规则，保留原始目录，清单记录原状态、原清单 SHA-256、来源路径及重新解析时间。不会补造缺少的响应，不接受 HTTP 失败冒充成功，不更新时间为重新抓取时间；新目录仍需通过完整证据验证。
