# 文档维护规则

[返回文档总索引](../README.md#文档索引)

适用范围：当前main的公开文档。根README是唯一总索引；本规则不新增开发或发布审批环节。

## 每类信息只指定一个主要维护位置

| 信息 | 主要位置 | 其他页面怎么引用 |
|---|---|---|
| 文档导航 | 根README | docs/README仅列技术细目与历史资料 |
| 当前实现范围 | progress.md、requirements.md | README保留简要结果，链接回范围说明 |
| 实际运行与测试 | acceptance.md、固定Release清单 | 写版本、环境、日期及实际范围，不能把本地自验证叫第三方认证 |
| 财务定义 | stage-1/feature-definitions.md及字段契约 | 改公式/单位必须更新定义、实现及必要回归 |
| 数据/特征覆盖 | 固定结果JSON及feature-coverage-v0.3.0.json | 不把人工完整样例、主样本和旧快照合并分母 |
| 已知缺口与升级 | gaps-and-weaknesses.md | 修复后同步移出“当前缺口”，保留必要历史说明 |
| 交付文件与发送文案 | interviewer-handoff.md、submission-message.md | 使用固定标签和真实文件名，不发本机路径给面试官 |
| 架构取舍 | architecture.md、decisions.md | 记录问题、选择、代价与适用范围，避免复制逐轮聊天 |

## 什么时候更新

新增或改变入口时，同批更新README索引和运行说明。完成一项缺口时，同批更新progress、gaps及对应验收证据。数据批次变化时，重新核对README摘要、showcase结果和覆盖JSON；新采样不能自动继承旧人工口径声明。

历史计划、阶段协作及旧验收只补明确的日期/版本提示，不把旧计数改成新结果。发布资产、标签及SHA-256保持冻结，文档整理在main正常提交；若要修订已交付文件，用新的版本发布并重新验证，不覆盖已有版本。

## 轻量检查

```bash
python scripts/check_docs.py
```

检查仓库Markdown内联链接的本地相对路径及Markdown标题锚点，跳过代码围栏和生成目录；离线、只读、标准库实现。退出0表示本地引用完整，1表示有坏链。它不请求远端，不保证外部网站一直可用，也不替代财务数字或浏览器排版核对。完整verify_offline.py已调用该检查。

提交前核对新增文件是否能从根README直接或经参考目录找到，文案是否区分“已实现、已验证、计划”，交付链接是否仍指向正确标签。对低影响文档调整使用链接/锚点检查即可；公式、数据或运行行为变化再执行相应业务回归。

## 对外表述约束

“12项公式已实现”不等于“八家公司所有12项都有值”；768/768重放包括空值和原因一致。两个网站数值相等不证明独立上游或相同修订语义。受控/核对事实重建输入与供应商原始响应分开说明。手选八公司回测不证明投资策略有效。
