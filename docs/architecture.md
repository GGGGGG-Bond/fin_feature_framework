# 架构

```text
HTTP尝试/分页 → 不可变响应文件 → 采集单元事务
                                ↓
                     内容版本 / 逐次观察 / 当前选择
                                ↓
                     标准化清洗 → 12个特征 → 质量与血缘报告
                                ↓
                      离线重放 / 截至日 / 修订刷新

第二来源 → 独立映射和核验 → 差异/不可比/缺失报告
```

| 模块 | 职责 |
|---|---|
| crawler、ingestion | 限频、分页、逐次尝试留证、单元协调、失败传播 |
| storage | SQLite迁移、事务、原始文件、版本/观察及清洗和计算输入 |
| cleaning | 缺失/异常/去重、字段标准化、当前版本与质量诊断 |
| features | 注册式特征、期间依赖、可比性门禁、不可计算原因 |
| source_sample、reconcile、reference_check | 第二来源采样、数值比较、官方参考核查 |
| asof、refresh、replay、delivery | 保存历史选择、修订失效与重算、输入重放与报告 |

SQLite与文件系统不具备共同事务：响应文件先不可变发布，数据库业务写入按单元原子提交，孤儿与未完成状态由只读对账报告。失败时不删除证据。

清洗保留原始计量证据，在明确单位映射后计算标准值。来源/合并范围/累计口径和版本不能证明可比时拒算，不用表名相同代替可比证据。

截至日分系统观察时间与明确公开时间；未知修订公开时间拒绝回填。重放用保存输入与当前代码，不是历史软件环境恢复。
