## 开工前阅读与交付

按顺序阅读 [数据字典](data-dictionary.md)、[12 个特征定义](feature-definitions.md)、[字段权威与运行契约](field-authority.md)、[验收测试矩阵](test-matrix.md)。这四份文档共同构成阶段 1 的验收依据；遇到冲突提交架构审阅，不能自行猜字段单位或财务口径。

实现 agent 从最新 origin/main 建立独立分支/worktree。先交付正确性修复和来源语义入口，再交付特征口径与回归；每批提交携带任务编号、基准/结果 commit、验证结果与文档更新。架构 agent 负责独立审阅，本聊天不会与实现 agent 同时修改其工作树。

## 必须交付

修复 P1-01 至 P1-06；限定 recent_periods 的实际采集范围；接入 YAML 清洗配置；禁止空值覆盖有效权威字段；引入唯一运行时语义入口与统一诊断；按定义计算 12 个特征；补齐异常路径回归、可安装性验证和 CLI 分析口径说明。

现有名称保留，但 gross_margin_feat、debt_asset_ratio 输出改为小数；ROE 两特征改为去年同期比较。这是明确的语义兼容变更，定义版本 stage1-v1 必须进入运行摘要和文档。不能把旧库里未重算的值标为新定义。现有测试可根据明确变化修订预期，必须保留原缺陷场景的独立回归，不能仅删掉失败测试。

阶段 1 仅允许为 features 增加一个 definition_version 标记及相应查询隔离，不建设完整版本存储、双源核验、历史 as_of 或全部依赖传播；不删除已有历史库，不自动全量重算用户数据。完整迁移与历史能力按后续阶段处理。

## 完成条件
