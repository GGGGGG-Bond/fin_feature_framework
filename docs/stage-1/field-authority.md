# 字段权威与运行契约

版本：stage1-v1。适用阶段 1；完整来源版本存储与血缘数据库留待阶段 2。

## 唯一语义入口和诊断

标准化层按原报表记录构造 SemanticRecord（或等价结构），封装 metrics、币种/单位、scope、period_basis、行业、comparison_basis、原记录引用与映射依据。合并上下文须为每个字段保留其对应的 SemanticRecord/元信息引用；不能让 IS 流量、BS 余额和 FI 回退字段共用一个顶层 basis 或 record_ref。特征层只消费该入口产生的上下文，不反查 API 原字段、猜类型码或自行做单位转换。独立执行 features 时也经此入口关联 clean 中实际选用记录对应的 raw 输入；关联不唯一或不存在则 unknown，不能按公司+报告期任意另取一条补证据。

可保持 Feature.calculate(ctx)->float|None 接口。上下文的 current/previous/year_ago 数值应符合数据字典，新增语义信息及单季值可通过向后兼容默认字段提供。引擎统一收集按 feature_name 索引的结构化诊断；单季值由标准化/上下文构建层提供，特征类不得各写一套季度差分。

最小诊断：secucode、report_date、feature_name 或字段、reason_code、原记录引用、所选/被拒来源、detail、definition_version。reason_code 至少含 missing_input、unknown_unit、unknown_scope、incomparable_basis、missing_comparison_period、non_positive_comparison_base、not_applicable、invalid_value、source_conflict、fallback_used。批量结果返回数值写入数及原因计数；现有日志/报告可承载诊断，本阶段不强制新增完整血缘表。

## 权威字段选择

| 字段组 | 优先路径 | 缺失与冲突 |
|---|---|---|
| 营业总收入、归母净利润 | 有效 IS 值 | 仅当 FI 的公司、报告期、单位、合并和修订口径可比时允许回退，并记录 fallback_used |
| 加权平均 ROE、销售毛利率 | 定义已核验的 FI 值 | 不用净利润/期末权益臆算加权 ROE；不从净利率推毛利率 |
| 总资产、总负债、权益合计 | 有效 BS 值 | 不从别表或会计等式补齐缺失值；字段缺失时按具体特征诊断 |
| 资产负债率 | BS 负债/资产 | 原 API 百分值仅对照，不能代替缺失分母 |
| 流动比率 | 可信 BS 明细自算或单位已核验的 CURRENT_RATIO | 当前探测无流动明细，禁止构造；单位未知则不可计算 |
| 标识与披露信息 | 每份 SemanticRecord 自己的元信息 | 不由另一张表覆盖其 notice_date、来源或可比状态 |

禁止整体 dict.update 合并。非权威表 None 不覆盖有效权威值。IS=110、FI=100 且都有效时选择 IS=110，记录 source_conflict；不取平均、不静默忽略差异。IS 缺失、FI 有效且可比时可回退；元信息不明确则 None。任一回退均保留精确来源引用，不把混合字段标成同一份报表。

金额一致性默认容差 max(0.01 标准金额单位, 1e-8*max(abs(a),abs(b)))；超出阈值记录差异，阈值可显式配置。非标准单位不使用该容差。此处是同源跨表核对规则，阶段 3 双源各字段容差另行冻结。

## 采集范围与增量

recent_periods=N：每家公司、每种报表按来源返回的 report_date 降序选择最近 N 个不同合法报告期。N 是上限，少于 N 不补造；None 表示不限制，非正整数或错误类型在请求前报配置错误。不能以今天推算截止日期、按行数截 N、或使用整个样本最新报告期代替每家公司最新期。

保留目标期内来源实际返回且现有存储可容纳的记录；不声称恢复接口未提供的历史版本。只有适配器已确认来源保证 report_date 降序、且本批已获取页通过单调性检查，才允许在目标期边界完整获取后停止。来源不保证排序时不得提前停止；可以在显式允许的扫描上限内完整扫描后选择，或在写库前报告不支持，不能默默扩大扫描。排序异常按单元失败处理。默认不自动额外采集 lookback；默认 4 期可能缺同比基准，应输出 missing_comparison_period。需要 8 或 12 期时显式配置。各表可有不同可用期，特征按实际日期匹配并报告缺表，不声称 N 个统一完整输出期。

增量命令采用同样的有限报告期回扫和幂等写入，不能将 last_notice_date 用于 REPORTDATE 或 REPORT_DATE 条件。公告水位暂保留为观察信息；来源没有经确认的公告过滤能力时不伪造过滤。回扫窗口外的旧修订本阶段不能保证捕捉，报告必须注明扫描范围。

采集成功单元定义为“采集适配器/具体报表类型+公司+本次请求范围”，FI/IS/BS 分别处理；水位、事务与失败摘要使用同一单元 key。其中任何分页 HTTP 错误、业务错误或格式异常时，此单元不更新成功水位，不提交新的部分 raw 数据；其他成功单元可继续，但整体 CLI 退出非零并汇总失败。成功空响应必须由明确的 success 与合法结构确认；不能将失败当空成功。已有旧 raw 数据保留，重试不得造成重复写入。

## 清洗配置、当前结果与 CLI

YAML cleaning.outlier_thresholds、missing_strategy 确实传入流程。阈值统一使用数据字典标准单位，并在标准化后判断；默认 YAML 和 rules.py 随之更新，不能继续把百分数阈值作用于小数。未配置字段继承默认；显式覆盖优先；错误策略、倒置阈值、非法数值在开始写库前拒绝。默认规则取消负 BPS/权益的错误清除，未知单位 CURRENT_RATIO 不套用“倍数<=100”的阈值；负债率超 100% 需诊断而非自动丢弃。

每公司/表/报告期当前记录按公告日选最新；同日采用有效 entry_time 再采用可确定内容摘要顺序并记录歧义，不能声称是完整修订顺序。未知公告日不替换已知最新记录。阶段 1 同步修正当前清洗/特征结果被丢弃或不可计算时的残留：只处理本批次确定范围，不全表删除。历史不可变版本在阶段 2 实现。

features 最小定义隔离：为 features 增加 definition_version TEXT，原有无标记行按 legacy-unversioned 识别，新写入均标 stage1-v1。创建新库和已有库的加列操作均需幂等；不建立完整版本 schema。get_features、get_feature_series 和分组分析显式按目标定义过滤，不能混读；摘要报告被排除的旧行数。若新计算将覆盖同主键的 legacy 行，阶段 1 默认拒写并提示使用隔离的新库，保留旧库，不自动迁移/覆盖历史结果。

backtest 子命令暂保留兼容，帮助和报告改称“特征分组与后续盈利增长分析”；保留代理口径，输出不称投资收益、多空策略收益或交易绩效。原 long_short 字段可保留兼容，但展示为“最高组与最低组盈利增长差”。不接入行情数据。

安装验收：干净临时环境能按项目元数据安装并运行 CLI --help；修正无效 build backend 等实际打包缺陷。只改本项目，不修改其他项目解释器或全局依赖。
